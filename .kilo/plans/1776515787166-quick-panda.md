# Plan: New `organization` Subcommand for CLI

## Overview

Add a `new organization` subcommand to the CLI that creates a new organization article, following the same pattern as `location`, `species`, etc. The command will accept flags matching the fields in `OrganizationSchema` from `packages/types/src/Organization.ts`.

## Files to Create

### 1. `cli/src/commands/new/organization/command.ts`

Define the command builder with flags mirroring `OrganizationSchema`:

- `type` — parsed string (`OrganizationType` enum values or any string)
- `founded` — optional string (founding date/era)
- `dissolved` — optional string (dissolution date/era)
- `headquarters` — optional string
- `members` — CSV-parsed string array (member names)

Positional: `articleName` (organization name)

### 2. `cli/src/commands/new/organization/impl.ts`

Implement the command function. Builds template data from flags:

```ts
interface NewOrganizationCommandFlags extends NewCommandFlags {
  type?: string;
  founded?: string;
  dissolved?: string;
  headquarters?: string;
  members?: string[];
}
```

Calls `renderTemplate` with `template: "organization"` and `targetDir: getTargetPath("organizations")`, tags default to `["organizations"]`.

### 4. `cli/src/commands/new/commands.ts`

- Import `organizationCommandBuilder` from `./organization/command.js`
- Instantiate the command: `const organizationCommand = organizationCommandBuilder(defaultFlags);`

## Notes

- `members` flag accepts a comma-separated list of member names (e.g. `--members "Alice,Bob"`). Each becomes a `{ name: "..." }` object in the frontmatter, matching `OrganizationMemberSchema`.
- No type import needed beyond `string` since `OrganizationType` values are just strings and the schema already accepts `z.string()` as a fallback.
- The `Organization` type export from `@bastion-falls/types` should already be available (check `packages/types/src/index.ts` if needed).
